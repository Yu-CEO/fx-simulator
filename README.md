# 為替の「動く幅」を学ぶシミュレーター（fx-simulator）

米ドル／円の過去約10年分のデータから、「為替がどれくらいの幅で動くものか」「先のことは1本の線では決まらない」を見て学ぶための無料ツールです。ブラウザで開くだけで動きます。

## できること
- **過去のチャート**：米ドル／円の日次の値を「1年／3年／10年」で表示します
- **動く幅（帯）**：データの最終日から先（1週間＝5営業日／2週間＝10／3週間＝15／1か月＝20営業日。最初は1か月）に、過去の動きの大きさから作った「狭い帯」「広い帯」を重ねます。帯の真ん中は最終日の値で、中心の線は引きません
- **帯の答え合わせ**：過去のそれぞれの日に同じ作り方で帯を作ったとき、実際の値が帯の外に出た割合を出します。幅の計算方法4つを比べた表も出します
- **似た局面のその後**：直近20営業日の動きと似た過去の日のその後を、「全期間の基準」と並べて件数と散らばりで出します（過去の集計です）
- **注意書き・データの出どころ・データの最終日**を常に出します
- **今日の図（第2段階）**：ページを開くと、紺の帯のすぐ下で約18秒の動く図が1回だけ動き、最後の絵で止まります（「もう一度見る」で再生し直せます。OS の「動きを減らす」がオンのときは最後の絵だけ）。流れは ①1か月前に作った幅に、その後の値が入ったかの答え合わせ → ②旅行代（ドル払いの旅行代が いま10万円）の問い → ③帯が広がる図 → ④円安の場合・今のレートのまま・円高の場合の3つの金額 → ⑤シリーズ名「ドル円の幅、答え合わせつき」。答え合わせは「よくある幅の中に入った」「まれな幅の中に入った」「まれな幅の外に出た」の3通りです。同じ数字・同じ文言で、**TikTok 用の縦動画**（1080×1920・無音の mp4）も毎朝の取得のあとに自動で作ります

## 使い方
1. `index.html` をブラウザで開きます（ダブルクリックでOK。サーバー・インストールはいりません。インターネットにつながっていなくても動きます）
2. 上の「先の長さ」で 1週間／2週間／3週間／1か月、チャートの上で 1年／3年／10年 を選びます
3. 3年・10年・答え合わせ・似た局面は、過去約9年分のデータを読み終えると自動で表示されます（それまでは「読み込み中…」）

## 縦動画（毎朝の自動生成・TikTok へは手で投稿）
- 毎朝のデータ取得が**成功し、データの最終日が前回から変わった日だけ**、GitHub Actions（`.github/workflows/make_video.yml`）が `fx_daily_YYYY-MM-DD.mp4`（日付＝データの最終日）を1本作ります。土日・祝日などで新しい値がない日、取得に失敗した日、1か月前の帯が作れない日は作りません（理由は Actions のログに出ます。失敗にはしません）
- 動画は **Actions の成果物（artifact）に7日間だけ**保存します（保存日数は `make_video.yml` の `VIDEO_RETENTION_DAYS`）。**commit・push はしません**（動画を git の履歴に入れません。書き出し先 `video_output/` は `.gitignore` 済みで、CI の `tools/check_no_video.py` が確かめます）。サイト（GitHub Pages）にも置きません
- 取り出し方：GitHub のリポジトリの Actions → 「為替データの自動取得」（または「縦動画の自動生成」）の実行を開く → 一番下の Artifacts から `fx_daily_…` をダウンロード（zip の中に mp4）。音は TikTok で付け、投稿は作者が手で行います（自動投稿はしません。TikTok の認証情報はどこにも持ちません）
- 余白（上160・下420・左64・右160）・文字の大きさ（注意書き34・判定70・金額60）・旅行代の金額・秒数・シリーズ名は `js/story_config.js` だけで変えられます。**最初の1本は作者の実機（TikTok の下書き）で確認して調整します**
- 作り方：`tools/video/frame.html`（サイトの今日の図と同じ `js/story_*.js` で1コマを描くページ）を Playwright（Chromium）で開き、時刻を進めながら1コマ（30コマ/秒）ずつ画像にして、ffmpeg で H.264 の mp4 につなぎます。サイトと同じ描く関数を使うので、見た目はずれません。書き出したあと、大きさ（1080×1920）・長さ（15〜20秒）・ファイル名・無音を自動で確かめ、合わなければ失敗にします
- **道具とフォントの利用条件**（Actions の中だけで使い、サイトの画面・データ取得には持ち込みません）：
  - Playwright（Apache License 2.0）・Chromium（BSD などのオープンソースライセンス）：無料で使えます。生成した動画にクレジット表示は要りません
  - ffmpeg（LGPL／GPL）：無料で使えます。動画を作るだけで、ffmpeg 自体を配布しないので、動画へのクレジット表示は要りません
  - Noto Sans CJK JP（SIL Open Font License 1.1。Ubuntu の `fonts-noto-cjk`）：商用の動画・画像への利用も無料で、クレジット表示は要りません（フォントそのものを単体で売ることはできません）。サイトには外部フォントを読み込まず、端末の文字を使います
  - いずれもこの確認は 2026-11-19 時点のライセンス表記の把握です。ライセンスが変わっていないかは、道具のバージョンを上げるときに見直してください
- 手元で試す（任意）：`.venv` の中に `pip install -r tools/video/requirements.txt` と `python -m playwright install chromium`、ffmpeg と日本語フォントを入れて、`python tools/video/make_video.py` を動かします（Chromium を別に入れてあるときは `--chromium-path` で指定）。数分かかります

## データの出どころと更新
- 為替データ：**欧州中央銀行（ECB）の参照レート**を、[Frankfurter](https://frankfurter.dev/) の ECB 提供分（`/v2/providers/ECB/rates`）から取得します。集約レート（複数の元を混ぜた既定の値）は使いません（日々の動きがならされて帯が狭く出るため。仕様 v3.2）
- ECB の値はユーロ基準です。米ドル／円は、ECB のユーロ／米ドルとユーロ／円から計算したクロスレートで、**Frankfurter 側で計算されて返ってきます**（取得ツールでは計算しません。2026-11-18 に実際の返答で確認）
- 参照レートです。リアルタイムの値ではなく、1日1回公表される値です。土日と ECB の休業日の値はありません（営業日＝ECB が値を公表した日。値の無い日を補いません）
- 利用条件：確認済みです。Frankfurter の FAQ では、保存・キャッシュは推奨、提供元に直接問い合わせる場合は提供元の規約が適用されるとあり、ECB の規約（`https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html`）は出典を書けば利用できます。ECB は参照レートを「情報提供のため」の値と位置づけているので、画面には出典（欧州中央銀行）と「リアルタイムではない・保証はない」を出しています
- 毎日 日本時間10:00ごろに GitHub Actions（`.github/workflows/update_data.yml`）が1回だけ取得し、変化があれば `data/` を更新します。取得に失敗したときはファイルを書き換えず、前日までのデータのまま表示します
- `data/usdjpy_source.csv` は取得した元の値そのまま（丸め・補完なし。ECB が値を公表した日だけ）。画面用の `data/usdjpy_recent.js`・`usdjpy_older.js` は、それを小数第3位に丸めたものです（念のため土日は除きます）。手で書き換えないでください
- 帯・答え合わせ・似た局面の数字は、上のデータをもとに当サイトで計算したものです

## 開発者向けの使い方
Node.js（20以上）と Python（3.10以上）があれば動きます。サイトとデータ取得は外部ライブラリを使いません（Python の隔離環境〈venv〉もいりません）。縦動画づくり（Actions の中だけ）は Playwright・ffmpeg を使います（上の「縦動画」参照）。

```
node --test tests/                                   # 計算のテスト（作ったデータを使う）
python -m unittest discover -s tests -p "test_*.py"  # 取得・変換のテスト（本物の API には問い合わせない）
python tools/check_size.py                           # 読む量が上限以内か（最初 80KB・10個、全体 200KB）
python tools/update_data.py                          # データを取得して更新（1日1回だけ。同じ日の2回目は何もしない）
python tools/update_data.py --rebuild                # 取得せず、CSV から画面用データだけを作り直す
node tools/add_band_state.js                         # 全期間で計算した最終日の状態と、今日の図の基準（1か月前の状態・答え合わせの通算）を usdjpy_recent.js の末尾に書く（取得・入れ直しのあとに必ず動かす）
python tools/check_no_video.py --history             # 動画ファイルが git（履歴を含む）に入っていないか
python tools/video/make_video.py                     # 縦動画を作る（Actions の中で動かす。手元では上の「手元で試す」）
python tools/update_data.py --reimport               # 今の CSV を捨てて約10年分を取り直す（データ元を替えたときの1回だけ）
node tools/compare_band_methods.js                   # 幅の計算方法4つを比べ、docs/band_methods.md と data/band_compare.js を書く
```

幅の計算方法は `js/band_config.js` の `methodName` で決まります。替えるときは `compare_band_methods.js` で比べ直して作者が決め、ここを書き換えます（毎日の自動更新では替わりません）。

## 注意
- 過去の為替データを決まった計算式で集計・表示するだけのツールです。**投資の助言ではありません**。将来の値動きを示すものではなく、特定の商品・取引・業者をすすめるものでもありません
- 帯は「過去の動きの大きさ」から作った幅で、実際の値は帯の外に出ることがあります（「くわしく」の答え合わせのとおりです）
- FX（外国為替証拠金取引）は元本を超える損失が出ることがあります。実際の判断はご自身の責任で行ってください
- 入力内容の保存・送信はありません。画面から外部への通信もありません
