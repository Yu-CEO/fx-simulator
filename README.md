# 為替の「動く幅」を学ぶシミュレーター（fx-simulator）

米ドル／円の過去約10年分のデータから、「為替がどれくらいの幅で動くものか」「先のことは1本の線では決まらない」を見て学ぶための無料ツールです。ブラウザで開くだけで動きます。

## できること
- **過去のチャート**：米ドル／円の日次の値を「1年／3年／10年」で表示します
- **動く幅（帯）**：データの最終日から先（1週間＝5営業日／2週間＝10／3週間＝15／4週間＝20。最初は4週間）に、過去の動きの大きさから作った「狭い帯」「広い帯」を重ねます。帯の真ん中は最終日の値で、中心の線は引きません
- **帯の答え合わせ**：過去のそれぞれの日に同じ作り方で帯を作ったとき、実際の値が帯の外に出た割合を出します。幅の計算方法4つを比べた表も出します
- **似た局面のその後**：直近20営業日の動きと似た過去の日のその後を、「全期間の基準」と並べて件数と散らばりで出します（過去の集計です）
- **注意書き・データの出どころ・データの最終日**を常に出します

## 使い方
1. `index.html` をブラウザで開きます（ダブルクリックでOK。サーバー・インストールはいりません。インターネットにつながっていなくても動きます）
2. 上の「先の長さ」で 1週間／2週間／3週間／4週間、チャートの上で 1年／3年／10年 を選びます
3. 3年・10年・答え合わせ・似た局面は、過去約9年分のデータを読み終えると自動で表示されます（それまでは「読み込み中…」）

## データの出どころと更新
- 為替データ：**欧州中央銀行（ECB）の参照レート**を、[Frankfurter](https://frankfurter.dev/) の ECB 提供分（`/v2/providers/ECB/rates`）から取得します。集約レート（複数の元を混ぜた既定の値）は使いません（日々の動きがならされて帯が狭く出るため。仕様 v3.2）
- ECB の値はユーロ基準です。米ドル／円は、ECB のユーロ／米ドルとユーロ／円から計算したクロスレートで、**Frankfurter 側で計算されて返ってきます**（取得ツールでは計算しません。2026-11-18 に実際の返答で確認）
- 参照レートです。リアルタイムの値ではなく、1日1回公表される値です。土日と ECB の休業日の値はありません（営業日＝ECB が値を公表した日。値の無い日を補いません）
- 利用条件：確認済みです。Frankfurter の FAQ では、保存・キャッシュは推奨、提供元に直接問い合わせる場合は提供元の規約が適用されるとあり、ECB の規約（`https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html`）は出典を書けば利用できます。ECB は参照レートを「情報提供のため」の値と位置づけているので、画面には出典（欧州中央銀行）と「リアルタイムではない・保証はない」を出しています
- 毎日 日本時間10:00ごろに GitHub Actions（`.github/workflows/update_data.yml`）が1回だけ取得し、変化があれば `data/` を更新します。取得に失敗したときはファイルを書き換えず、前日までのデータのまま表示します
- `data/usdjpy_source.csv` は取得した元の値そのまま（丸め・補完なし。ECB が値を公表した日だけ）。画面用の `data/usdjpy_recent.js`・`usdjpy_older.js` は、それを小数第3位に丸めたものです（念のため土日は除きます）。手で書き換えないでください
- 帯・答え合わせ・似た局面の数字は、上のデータをもとに当サイトで計算したものです

## 開発者向けの使い方
Node.js（20以上）と Python（3.10以上）があれば動きます。外部ライブラリは使いません（仮想環境もいりません）。

```
node --test tests/                                   # 計算のテスト（作ったデータを使う）
python -m unittest discover -s tests -p "test_*.py"  # 取得・変換のテスト（本物の API には問い合わせない）
python tools/check_size.py                           # 読む量が上限以内か（最初 80KB・10個、全体 200KB）
python tools/update_data.py                          # データを取得して更新（1日1回だけ。同じ日の2回目は何もしない）
python tools/update_data.py --rebuild                # 取得せず、CSV から画面用データだけを作り直す
node tools/add_band_state.js                         # 全期間で計算した最終日の状態を usdjpy_recent.js の末尾に書く（取得・入れ直しのあとに必ず動かす）
python tools/update_data.py --reimport               # 今の CSV を捨てて約10年分を取り直す（データ元を替えたときの1回だけ）
node tools/compare_band_methods.js                   # 幅の計算方法4つを比べ、docs/band_methods.md と data/band_compare.js を書く
```

幅の計算方法は `js/band_config.js` の `methodName` で決まります。替えるときは `compare_band_methods.js` で比べ直して作者が決め、ここを書き換えます（毎日の自動更新では替わりません）。

## ファイルの地図
| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み（チャート・ボタン・帯の数字・答え合わせ・似た局面・注意書き）と、最初に読むファイルの指定だけ |
| `css/style.css` | 見た目（色・文字・余白・チャート・表）。外部フォントなし |
| `js/main.js` | 入口。データの確認 → 方法の読み込み → 01 の表示 → 過去の分を読んで 02・03 の表示。ボタンでの表示し直し |
| `js/data_loader.js` | 採用した方法のファイル1つと、後から読む分（過去約9年分など）を `<script>` で読む。データをつなぐ |
| `js/band_config.js` | 帯の設定（採用した方法・短い名前・先の長さ 5・10・15・20 と最初の 20・250営業日・目標 68％／95％・合格の線 65％／93％・λ） |
| `js/band_calc.js` | 日々の変化と帯（最終日から先のラッパ型）の計算。画面には触れない |
| `js/band_methods/rolling_std.js` | 方法①：直近1年の動き（標本標準偏差） |
| `js/band_methods/ewma.js` | 方法②：直近を重く見た動き（EWMA、λ＝0.94） |
| `js/band_methods/garch11.js` | 方法③：GARCH(1,1)（ω・α・β の推定つき） |
| `js/band_methods/kalman_local_level.js` | 方法④：カルマンフィルタ（ローカルレベル。v3.2 の作り）で変動の大きさを推定 |
| `js/band_backtest_calc.js` | 帯の答え合わせの計算。画面には触れない |
| `js/similar_calc.js` | 似た局面と全期間の基準の集計（PERCENTILE.INC と同じ線形補間）。画面には触れない |
| `js/result_cache.js` | 答え合わせ・似た局面の結果を先の長さごとに覚える（同じ選択では計算し直さない） |
| `js/format.js` | 数字の表示形式（円・％・件数・日付） |
| `js/band_view.js` | 01 の表示（SVG のチャート・拡大図・帯の数字・読み込み中の表示） |
| `js/stats_view.js` | 02・03 の表示（答え合わせ・比べ方の表・似た局面の表） |
| `data/usdjpy_source.csv` | 取得した元の値（自動更新） |
| `data/usdjpy_recent.js` | 画面用データ：直近 約1年＋20営業日（最初に読む。自動生成） |
| `data/usdjpy_older.js` | 画面用データ：それより前の分（後から読む。自動生成） |
| `data/band_compare.js` | 幅の計算方法の比較結果（02 の表に使う。`compare_band_methods.js` が生成） |
| `tools/fetch_frankfurter.py` | Frankfurter の ECB 提供分から期間を指定して取得し、「日付と値の一覧」の共通の形で返すだけ（提供元ごとの違いはここだけ） |
| `tools/data_files.py` | CSV・画面用データの読み書き（丸め・週末と使えない値の除外・期間で2つに分ける） |
| `tools/update_data.py` | 1日1回だけの確認 → 取得 → 形の確認 → まとめて書き換え。失敗したら書き換えない |
| `tools/check_size.py` | 読む量（大きさ・数）が上限以内かを調べる（CI で動かす） |
| `tools/compare_band_methods.js` | 4つの方法を同じ日の集まりで答え合わせし、採用する方法を選ぶ |
| `tools/kalman_legacy_check.js` | 旧い方法④（v3.1）が固定の重みの EWMA と同じだったことを数で示す（文書用） |
| `tools/add_band_state.js` | 全期間で計算した方法④の最終日の状態を `usdjpy_recent.js` に書く（画面の帯の S(h) に使う） |
| `tools/band_methods_report.js` | 比較の結果を `docs/band_methods.md` と `data/band_compare.js` に書く |
| `tests/*.test.js` | 計算・表示・言葉の自動テスト（`node --test`） |
| `tests/test_update_data.py` | 取得・変換・大きさの自動テスト（`unittest`） |
| `ci/confidential_check.py` | 機密チェック（テンプレートのコピー） |
| `.github/workflows/ci.yml` | CI（テスト・大きさ・機密チェック・公開） |
| `.github/workflows/update_data.yml` | 毎日 UTC 01:00（日本時間10:00）にデータを取得 |
| `docs/` | 要求仕様・比較の結果（`band_methods.md`）・レビューなど（リポジトリには上げない） |

## 注意
- 過去の為替データを決まった計算式で集計・表示するだけのツールです。**投資の助言ではありません**。将来の値動きを示すものではなく、特定の商品・取引・業者をすすめるものでもありません
- 帯は「過去の動きの大きさ」から作った幅で、実際の値は帯の外に出ることがあります（02 の答え合わせのとおりです）
- FX（外国為替証拠金取引）は元本を超える損失が出ることがあります。実際の判断はご自身の責任で行ってください
- 入力内容の保存・送信はありません。画面から外部への通信もありません
